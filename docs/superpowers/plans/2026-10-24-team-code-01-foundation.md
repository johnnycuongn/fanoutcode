# Team Code 01 — Foundation and Standards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the Team Code repository so every later plan lands on the same scaffold: a Cargo workspace with `teamcode-core` and the unchanged `livespec-core`, a Tauri 2 shell that creates `w-<n>` windows from Rust, a Vite + React 19 + Tailwind v4 webview with the two themes as tokens, generated IPC bindings, SQLite with numbered migrations, the module-store pattern, the engineering rules as files and as lint, and the quality gates wired into lefthook and CI.

**Architecture:** Three layers as in LiveSpec: `crates/teamcode-core` (no Tauri; domain types, ids, SQLite, window registry, recent list) → `src-tauri` (thin: `AppState`, windows, commands exported by tauri-specta) → `src/` (React, module stores read with `useSyncExternalStore`, bindings consumed only from `src/lib/bindings.ts`). This plan builds the commands and storage behind the start screen and first run (`windows_*`, `settings_first_run_*`, recent list); the screens themselves are Plan 06's, which composes them from Plan 02's primitives. `App.tsx` here is a placeholder root page.

**Tech Stack:** Rust stable, Tauri 2, tauri-specta 2 (specta + specta-typescript), rusqlite (bundled), chrono, serde; Node 22, Vite 7, React 19, TypeScript 5.x strict, Tailwind v4 via `@tailwindcss/vite`, Fontsource variable fonts, Vitest 3 with jsdom and `@testing-library/react`, ESLint 9 flat config with typescript-eslint, Prettier 3, lefthook, GitHub Actions on `macos-14`.

**Spec:** `docs/superpowers/specs/2026-10-24-team-code-design.md` (§3, §4.4, §11.1, §14, §15). Contracts: `docs/superpowers/plans/2026-10-24-team-code-00-overview-and-contracts.md`. LiveSpec reference: `github.com/johnnycuongn/live-spec` at commit `c55834b`.

## Global Constraints

- macOS first, Apple Silicon first; code kept portable (spec §2).
- Tauri 2; Rust stable; Node 22; React 19; TypeScript 5.x strict; Vite; Tailwind v4 via `@tailwindcss/vite`, no `tailwind.config` (§3, LiveSpec convention).
- Three layers: `crates/teamcode-core` never depends on Tauri; `src-tauri` stays thin; the webview has no state library and uses module stores read with `useSyncExternalStore` (§3, §14).
- IPC types are generated by `tauri-specta` into `src/lib/bindings.ts`; hand-written mirrors are forbidden (§15.1).
- Raw `<input>`, `<select>`, `<textarea>`, `<button>`, `<dialog>` appear only under `src/components/ui/`; hex colours and inline colour styles appear only in the theme file. ESLint fails the build otherwise (§15.3).
- Semantic Tailwind tokens only: `bg-page`, `bg-bar`, `bg-well`, `bg-card`, `border-line`, `text-ink`, `text-mute`, `text-accent`, `text-ok`, `text-warn`, `text-bad`, plus `stage-spec|plan|build|review|test|commit|done` (§11.1).
- Fonts bundled from Fontsource, never fetched: Inter, JetBrains Mono, Literata. CSP `default-src 'self'` (§3, §14).
- Secrets live in the OS keychain under service `app.teamcode.desktop`, never cross IPC (§14).
- Every id that becomes a path matches `^[a-z]+-[0-9a-f-]{1,40}$` before use (§14).
- Model and agent output renders only through `MiniMarkdown` or xterm, never `innerHTML` (§14).
- Nothing a user triggers takes longer than 250 ms to respond; `prefers-reduced-motion` turns springs into 150 ms eases and stops loops (§11.3).
- File size budgets: component under about 200 lines, store under 300, Rust module under 500 (§15.1).
- Naming: components `PascalCase.tsx`, lib and stores `camelCase.ts`, Rust `snake_case`; IPC commands `domain_verb` in snake_case; events `kebab-case` (§15.1, contracts).
- Commits follow Conventional Commits (§15.4). Every task ends with the quality gates in §15.4 passing for the code it touched.
- Crate names: `teamcode-core` (lib `teamcode_core`), `livespec-core` (lib `livespec_core`), shell package `teamcode` (lib `teamcode_lib`). Bundle identifier `app.teamcode.desktop`. Database `<app_data>/teamcode.db` (contracts).
- `livespec-core` is copied from LiveSpec unchanged: no edits, no renames; adaptations live in `teamcode-core` or the shell (§14).
- Serde convention for every Team Code type (contracts amendment A1): no `rename_all`, so fields stay `snake_case` and variants keep their Rust names (`"Spec"`, `"NeedsYou"`); unit-only enums serialise as plain strings; every data-carrying enum is internally tagged with `#[serde(tag = "type")]`; id newtypes are `#[serde(transparent)]`. Serde cannot internally tag a tuple variant whose payload is a string or a unit enum (it fails at runtime, not at compile time), so every variant of an internally tagged enum is a unit variant or a struct variant with named fields; no tuple variants, no `content = "…"` (amendment A17). Here that means `Container::Project { id }`, `Container::Workspace { id }`, `MemoryLocation::Folder { path }`, `PaneContent::Task { task_id }`, `PaneContent::TeamCanvas { task_id }`. The TypeScript is therefore `{ type: "NeedsYou", reason: { type: "Replied", first_line: "…" } }` and `{ type: "Project", id: "p-1" }`.

## Review Focus

1. **A recent project whose folder was deleted or moved.** The start screen must still list it, marked missing, and opening it must fail with an instruction, not a crash. Pinned in Task 5 (`recent::list` marks `missing`) and Task 13 (`windows_open_project` returns `Error::Precondition`).
2. **An enum that serialises in a unit test but fails at runtime.** Serde rejects internally tagged tuple variants over strings only when a value is serialised, so every data-carrying enum must be round-tripped in a test, including `PaneContent::TeamCanvas { task_id }`, and none may carry a tuple variant (A17). Pinned in Task 3.
3. **First launch: `<app_data>` does not exist yet.** `db::open` must create the parent folders rather than fail on the first run. Pinned in Task 4.
4. **A migration that fails halfway.** The database must stay at the previous version with nothing from the failed file applied, so a fixed build can retry. Pinned in Task 4.
5. **Theme System while macOS switches appearance at night.** The `data-theme` attribute must follow the OS while the preference is System and ignore the OS once the preference is Light or Dark. Pinned in Task 8.
6. **`localStorage` throwing (private mode, cleared site data).** The theme mirror must fall back to System and never block first paint. Pinned in Task 8.

export interface Store<T extends object> {
  get(): T;

# Team Code 07 — Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Kanban board feature (`src/features/board/`): seven stage columns, cards at three detail levels, drag and drop through `tasks_move`, filters, the card menu, the three workspace board modes, board motion and empty states, all driven by a module store fed by `tasks_list` and the task events.

**Architecture:** One feature folder with pure modules (chip text, filters, column grouping, drop resolution, activity reduction) tested directly by Vitest, a `boardStore` module store (board view state) read with `useSyncExternalStore` beside Plan 06's shared `tasksStore` (the task cache the board writes from `tasks_list` and `task-changed`), and presentational components composed only from Plan 02 primitives. The host (Plan 06, tab zero) passes the window's container, its projects, the resolved settings and the ⌘1–⌘9 focus as props; the board emits open-task intents back and owns nothing about windows or views. Every IPC call goes through one adapter file, `src/features/board/ipc.ts`, so tests mock one module and the generated binding names live in one place.

**Tech Stack:** React 19, TypeScript 5 strict, dnd-kit (`@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/modifiers`), Motion (`motion/react`), Vitest + Testing Library (jsdom), tauri-specta bindings in `src/lib/bindings.ts`.

**Spec:** `docs/superpowers/specs/2026-10-24-team-code-design.md` (§6, §10.2, §10.6 board parts, §11.3, §13 `detail_level`, `workspace_board`, `workspace_project_layer`, `cost_overview`). Contracts: `docs/superpowers/plans/2026-10-24-team-code-00-overview-and-contracts.md`.

**Naming note:** this plan writes contract names (`tasks_move`, `task-changed`). tauri-specta exports commands camelCased (`commands.tasksMove`) and events as `events.taskChanged`; only `src/features/board/ipc.ts` touches those. Data-carrying enums are internally tagged (overview A1): `AgentState` is `{ type: 'Working' }`, `{ type: 'Idle' }` or `{ type: 'NeedsYou', reason: { type: 'Replied', first_line: '…' } }`, `HookEvent` is `{ type: 'PostToolUse', tool, input, response }` and so on, and `Container` is `{ type: 'Project', id }` / `{ type: 'Workspace', id }`; unit-only enums (`Stage`, `Priority`, `AgentKind`, `DetailLevel`, `WorktreeChoice`) stay plain strings. Code matches on `.type`; tests build containers only through `projectContainer` / `workspaceContainer` (Task 1) so the shape is spelled once.

## Global Constraints

- Tauri 2; Rust stable; Node 22; React 19; TypeScript 5.x strict; Vite; Tailwind v4 via `@tailwindcss/vite`, no `tailwind.config` (§3, LiveSpec convention).
- Three layers: `crates/teamcode-core` never depends on Tauri; `src-tauri` stays thin; the webview has no state library and uses module stores read with `useSyncExternalStore` (§3, §14).
- IPC types are generated by `tauri-specta` into `src/lib/bindings.ts`; hand-written mirrors are forbidden (§15.1).
- Raw `<input>`, `<select>`, `<textarea>`, `<button>`, `<dialog>` appear only under `src/components/ui/`; hex colours and inline colour styles appear only in the theme file. ESLint fails the build otherwise (§15.3).
- Semantic Tailwind tokens only: `bg-page`, `bg-bar`, `bg-well`, `bg-card`, `border-line`, `text-ink`, `text-mute`, `text-accent`, `text-ok`, `text-warn`, `text-bad`, plus `stage-spec|plan|build|review|test|commit|done` (§11.1).
- Model and agent output renders only through `MiniMarkdown` or xterm, never `innerHTML` (§14).
- Nothing a user triggers takes longer than 250 ms to respond; `prefers-reduced-motion` turns springs into 150 ms eases and stops loops (§11.3).
- File size budgets: component under about 200 lines, store under 300, Rust module under 500 (§15.1).
- Naming: components `PascalCase.tsx`, lib and stores `camelCase.ts`, Rust `snake_case`; IPC commands `domain_verb` in snake_case; events `kebab-case` (§15.1, this document).
- Commits follow Conventional Commits (§15.4). Every task ends with the quality gates in §15.4 passing for the code it touched.
- A feature imports another feature only through its `index.ts`; the board imports no other feature (§15.1).
- Board with 200 cards drags at 60 fps (§16): cards are memoised, selectors return stable references, and the elapsed-time tick re-renders only the elapsed leaf whose text changed.

## Review Focus

1. A `task-changed` for a task whose home project is not in this window's container (every window receives every event) must be ignored, never inserted as a foreign card — pinned in Task 4.
2. `tasks_move` rejected by the core (`Precondition`, e.g. Test without a test command): the card returns to its column, a toast shows the error text, nothing stays optimistically moved — pinned in Task 5.
3. A drag that ends after the task vanished (archived or moved from another window mid-drag): no IPC call, no crash — pinned in Task 11.
4. A `state_entered_at` in the future or unparsable: elapsed shows `0m`, never `NaN` or a negative — pinned in Task 6.
5. A `Replied` first line that is long or contains a newline: the chip stays one truncated line — pinned in Task 1.

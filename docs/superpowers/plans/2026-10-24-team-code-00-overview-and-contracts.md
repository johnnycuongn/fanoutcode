# Team Code Implementation Plans — Overview and Contracts

**Spec:** `docs/superpowers/specs/2026-10-24-team-code-design.md` (approved 2026-10-24). Every plan argues from it; section numbers below refer to it.

This document is read by every plan writer and every implementer before anything else. It fixes what must agree across plans: the repository layout, crate and module names, the core types, IPC command and event names, the event-log format, the memory-folder format, the settings and prompt resolution rules, the quality gates, and the order the plans build in. A plan may add names inside its own scope; it may not rename or reshape anything here. If a plan needs a shared name this document lacks, it lists it under "Proposed contract additions" at its end and the overview is updated before execution.

## Global constraints (copied from the spec, apply to every task)

- macOS first, Apple Silicon first; code kept portable (spec §2).
- Tauri 2; Rust stable; Node 22; React 19; TypeScript 5.x strict; Vite; Tailwind v4 via `@tailwindcss/vite`, no `tailwind.config` (§3, LiveSpec convention).
- Three layers: `crates/teamcode-core` never depends on Tauri; `src-tauri` stays thin; the webview has no state library and uses module stores read with `useSyncExternalStore` (§3, §14).
- IPC types are generated by `tauri-specta` into `src/lib/bindings.ts`; hand-written mirrors are forbidden (§15.1).
- Raw `<input>`, `<select>`, `<textarea>`, `<button>`, `<dialog>` appear only under `src/components/ui/`; hex colours and inline colour styles appear only in the theme file. ESLint fails the build otherwise (§15.3).
- Semantic Tailwind tokens only: `bg-page`, `bg-bar`, `bg-well`, `bg-card`, `border-line`, `text-ink`, `text-mute`, `text-accent`, `text-ok`, `text-warn`, `text-bad`, plus `stage-spec|plan|build|review|test|commit|done` (§11.1).
- Fonts bundled from Fontsource, never fetched: Inter, JetBrains Mono, Literata. CSP `default-src 'self'` (§3, §14).
- Secrets live in the OS keychain under service `app.teamcode.desktop`, never cross IPC (§14).
- Every id that becomes a path matches `^[a-z]+-[0-9a-f-]{1,40}$` before use (§14).
- Model and agent output renders only through `MiniMarkdown` or xterm, never `innerHTML` (§14).
- The app never commits, merges, rebases, pushes or deletes branches on its own; the Commit button exists only when "Team Code may commit" is on, default off (§6.6).
- Nothing a user triggers takes longer than 250 ms to respond; `prefers-reduced-motion` turns springs into 150 ms eases and stops loops (§11.3).
- File size budgets: component under about 200 lines, store under 300, Rust module under 500 (§15.1).
- Naming: components `PascalCase.tsx`, lib and stores `camelCase.ts`, Rust `snake_case`; IPC commands `domain_verb` in snake_case; events `kebab-case` (§15.1, this document).
- Commits follow Conventional Commits (§15.4). Every task ends with the quality gates in §15.4 passing for the code it touched.

## Hook event log (§7.3)

Each hook in the generated settings file runs `sh -c 'printf "%s\t%s\t" <EventName> "$(date -u +%FT%TZ)"; cat; printf "\n"' >> "<app_data>/events/<task-id>.jsonl"`. One line per event: `EventName<TAB>rfc3339<TAB>{claude payload json}`. The status-line command appends the same shape with `EventName = StatusLine`. The tailer parses into:

```rust
// hooks.rs
pub struct TaskEvent { seq: u64, at: DateTime<Utc>, task_id: TaskId, agent_id: Option<String>, event: HookEvent }
pub enum HookEvent {
    SessionStart { session_id: String, transcript_path: PathBuf },
    UserPromptSubmit,
    PreToolUse { tool: String, input: serde_json::Value },
    PostToolUse { tool: String, input: serde_json::Value, response: serde_json::Value },
    SubagentStart { agent_id: String, agent_type: String, description: Option<String> },
    SubagentStop { agent_id: String },
    PermissionRequest { tool: String },
    Notification { message: String },
    Stop { last_assistant_message: String, background_tasks: usize },
    StopFailure { message: String },
    StatusLine { cost_usd: f64, input_tokens: u64, output_tokens: u64, context_used_pct: f32 },
    Unknown { name: String },
}
```

Build conventions parsed from events and `plan.md` (§6.3): step lines `- [ ] 5. Title (after 2, 7)`; dispatch descriptions `Step 5 · frontend: …` or `Step 5, 6 · frontend: …`; sentinel last line.

## Memory folder (§8)

`<memory_root>/YYYY-MM-DD-<slug>/` with `intent.md`, `spec.md`, `plan.md`, `review.md`, `commits.md`, `index.md`. `index.md` front matter keys: `id, project, workspace, title, stage, state, jira, agent, branch, worktree, base (repo→sha map), claude_sessions (list), created, updated`; body is a `## Timeline` list, one line per entry: `- 2026-10-24T05:12Z · plan · entered` / `· handback: Plan written` / `· commit: <repo> <sha>`. `memory::TaskFolder` owns reads and writes; only the app rewrites `index.md`.

## Settings and prompts (§6.8, §13)

`settings::resolve<T: SettingKey>(scope: Scope) -> T::Value` where `Scope { app, workspace: Option<WorkspaceId>, project: Option<ProjectId>, task: Option<TaskId> }`, most specific wins. Exceptions: `prompts::assemble(stage: Stage, ctx: &PromptCtx) -> String` layers base (project override else app) + workspace fragment + task additions; `roster::resolve(scope) -> Vec<AgentDef>` unions app, workspace, project with name shadowing. Placeholders: `{{task.folder}} {{project.root}} {{project.context}} {{linked.projects}} {{worktree}} {{test.command}}`. Setting keys and defaults are the table in spec §13; the key names are the table's left column in `snake_case` (e.g. `detail_level`, `dock_position`, `team_view_arrangement`, `workspace_board`, `link_policy`, `may_commit`, `cost_overview`).

## IPC (shell `commands/*.rs`, exported by tauri-specta)

Commands return quickly; long work returns a `Channel`. Names, grouped; a plan may add commands in its domain with the same style.

- sessions: `sessions_open(task_id) -> SessionId`, `sessions_terminal(project_id) -> SessionId`, `sessions_attach(session_id, window_id, pane_id, on_data: Channel<Vec<u8>>) -> Scrollback`, `sessions_detach(session_id)`, `sessions_write(session_id, bytes)`, `sessions_resize(session_id, cols, rows)`, `sessions_stop(session_id)`, `sessions_bring(session_id, window_id, pane_id)`

## Amendments after plan review (binding)

Ten plans were written in parallel from the sections above. Their "Proposed contract additions" were reconciled on 2026-10-24 into the items below. Each item names the plans it binds; those plans were updated to match. Where a plan and this list disagree, this list wins.

- **A1 Enum serialisation (01, 03, 05, 07, 08, 09).** Every data-carrying enum in `teamcode_core` is internally tagged: `#[serde(tag = "type")]`. Unit-only enums serialise as plain strings. `AgentState::NeedsYou(HandbackReason)` becomes `AgentState::NeedsYou { reason: HandbackReason }` so the tags do not collide. `HookEvent` is tagged `type` as well. The TypeScript shape is therefore `{ type: "NeedsYou", reason: { type: "Replied", first_line: "…" } }`.
- **A2 Hand-back chip text (03, 06, 07, 08).** Canonical texts for `HandbackReason::StageDone` by stage: Spec "Spec ready", Plan "Plan written, go?", Build "Build done", Review "Review written", Test "Tests passed", Commit "Message drafted", Done "Done". `Replied { first_line }` shows the first line; `PermissionNeeded` "Permission needed"; `TestFailed` "Tests failed"; `Error` "Error". The Rust source of truth is `handback::chip_text(&HandbackReason, Stage)` (Plan 03). The TypeScript mirror is `handbackLabel(task)` in `src/lib/format.ts`, owned by Plan 06 (moved out of the sidebar feature); Plans 07 and 08 import it. A Rust test in Plan 03 writes `src/test/fixtures/handback.json` and a Vitest test in Plan 06 asserts the mirror matches it.
- **A3 Hook command and `HookSpec` (04, 05, 10).** The hook command buffers the payload before one write, so parallel subagent hooks cannot interleave: `sh -c 'IN=$(cat); printf "%s\t%s\t%s\n" "<EventName>" "$(date -u +%FT%TZ)" "$IN" >> "<app_data>/events/<task-id>.jsonl"'`. `HookSpec { event: String, matcher: Option<String>, command: String, timeout_s: Option<u32> }` is defined by Plan 05 and used by Plans 04 and 10.
- **A4 Windows (01, 06, 07, 10).** `WindowInfo { window_id: WindowId, title: String, container: Option<Container>, project_ids: Vec<ProjectId> }`. Commands, all owned by Plan 01: `windows_list`, `windows_current`, `windows_focus(window_id)`, `windows_focus_next`, `windows_close(window_id)`, `windows_recent`, `windows_open_project(path)`, `windows_open_workspace(path)`. `WindowRegistry::set_container(label, Container)` exists for Plan 10's workspace conversions. One window per container; opening a container already shown focuses that window.
- **A5 Component props and pane kinds (01, 04, 06, 07, 08, 09).** `TerminalPane({ sessionId, paneId, focused? })` exported from `@/features/views`, with a `ref` exposing `focus()`; the window id comes from `currentWindowId()`. `Board(BoardProps)` exactly as Plan 07 defines it; Plan 06 supplies `focusedProject` from `boardProject` and `currentWindowId`. `TaskPage(TaskPageProps)` exactly as Plan 08 defines it; Plan 06 renders it for `PaneContent::Task` and routes ⌘⏎, ⌘E, ⌘⇧A, ⌘J, ⌘⇧J and ⌃` to `TaskPageHandle`; Plan 09 supplies `renderTeam` and `onOpenTeamPane`. `PaneContent::TeamCanvas(TaskId)` is added to the domain (Plan 01) and rendered by Plan 06 through Plan 09's `CanvasPane`. `SplitDirection::Horizontal` means side by side (⌘D), `Vertical` means stacked (⌘⇧D).
- **A6 Observation commands and shapes (05, 07, 09, 10).** `hooks_list(task_id) -> Vec<TaskEvent>` and `hooks_plan_steps(task_id) -> PlanDoc` are canonical; Plan 09 uses them in place of `hooks_events` and `memory_plan_steps`. Plan 05 adds `tasks_activity(container) -> Vec<TaskActivity { task_id, current_file: Option<String>, plus: u32, minus: u32, team: Vec<TeamRow { name: String, state: AgentState }>, cost_usd: Option<f64> }>` for Plan 07's Medium and Detailed cards; live updates still come from `team-event`. `CostSummary` is Plan 05's shape (`cost_usd, input_tokens, output_tokens, estimated, live, by_project, by_task, by_stage, by_day, by_model: Vec<CostLine>`) plus `by_agent: Vec<CostLine>`; Plan 10's `CostsPanel` and Plan 09 read those names.
- **A7 Reply (03, 07, 08).** `StageAction::Reply { prompt: String }` replaces the unit variant. The core turns it into `Effect::InjectPrompt(prompt)`; Plan 04 delivers it when the session is idle. Plan 08's reply prefix format stands.
- **A8 Migrations (01, 03, 05, 09, 10).** `teamcode-core/migrations/00NN_<name>.sql`, where NN is the owning plan's number: `0001_initial`, `0003_core`, `0005_observation`, `0009_canvas`, `0010_workspaces`. Plan 09 renames its 0090 range accordingly.
- **A9 Gaps assigned (01, 09).** Plan 01 adds `src-tauri/src/secrets.rs`, LiveSpec's keychain module under service `app.teamcode.desktop` with `read(account) -> Result<Option<Secret>>`, `write(account, value)`, `delete(account)`; Plans 05 and 10 consume it. Plan 01's CSP is `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:` (the WASM allowance is for bundled dotLottie, never fetched). Plan 09 adds a final task: the Playwright smoke suite from spec §15.4 covering the board, the task page and the canvas against the dev build.
- **A10 Shared TypeScript helpers (01, 02, 07, 08).** `src/lib/motion.ts` is Plan 02's: `useReducedMotion`, `transitionFor(kind, reduced)`, `SPRING`, `EASE_REDUCED`, `GLOW_MS`, `REFLOW_MS`. `src/lib/theme.ts` (Plan 01) exports `SWATCHES` and `swatchClass(swatch, part: 'bg' | 'text' | 'edge')`; Plan 07 uses these instead of its own colour helpers. `createStore<T>` is Plan 01's API (`get`, `set`, `subscribe`, `use`, `useSelector`, `reset`); Plan 08 uses it. `src/test/{setup,ui}.ts` is Plan 02's harness. `src/lib/stores/{projectsStore,tasksStore}.ts` are Plan 06's shared stores; Plans 07 and 08 import them.

# Team Canvas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Team tab: a React Flow canvas (and an Outline mode) derived purely from `plan.md` and the task's hook event stream, with Hub graph and Flow canvas arrangements, three detail levels, Auto re-flow or Pinned layout with positions saved per task, three placement modes, two drill-in lenses, the spec's motion, and replay of a finished Build.

**Architecture:** `src/features/canvas/model.ts` and its sibling modules are pure functions from `PlanStep[]` plus `TaskEvent[]` to `CanvasNode[]` and `CanvasEdge[]`, tested without a DOM. A module store feeds them from `team-event`, `hooks_list`, `hooks_plan_steps`, `git_changes`, `cost_summary` and `settings_get`, runs elkjs for positions, and applies the Auto re-flow / Pinned policy. React Flow renders the graph; node bodies are plain components so they can be render-tested outside React Flow. Positions persist through two new commands over the `canvas_positions` table. The canvas reaches the task page through Plan 08's `TaskPageProps.renderTeam` and `onOpenTeamPane`, and its own pane through `PaneContent::TeamCanvas` (overview A5). A Playwright smoke suite drives the board, the task page and this canvas in the Vite dev server with the Tauri IPC mocked (overview A9).

**Tech Stack:** React 19, TypeScript 5.x strict, `@xyflow/react` 12, `elkjs` 0.9 (bundled build, no worker), `motion` 12, `@rive-app/react-canvas` 4, `@radix-ui/react-slider` (behind a new `Slider` primitive), Vitest + Testing Library (jsdom), `@playwright/test` 1.x (WebKit) with `@tauri-apps/api/mocks`, Rust `rusqlite` for the two commands, `tauri-specta` for bindings.

**Spec:** `docs/superpowers/specs/2026-10-24-team-code-design.md` — §10.7 in full, §6.3 (Build conventions), §7.3 (events), §10.5 (⌘⇧J), §11.3 (canvas motion), §13 (settings), §15 (standards; §15.4 for the smoke suite). Contracts: `docs/superpowers/plans/2026-10-24-team-code-00-overview-and-contracts.md`, including its binding amendments A1, A5, A6, A8 and A9, which this plan follows.

- Every id that becomes a path matches `^[a-z]+-[0-9a-f-]{1,40}$` before use (§14).
- Model and agent output renders only through `MiniMarkdown` or xterm, never `innerHTML` (§14).
- Nothing a user triggers takes longer than 250 ms to respond; `prefers-reduced-motion` turns springs into 150 ms eases and stops loops (§11.3).
- File size budgets: component under about 200 lines, store under 300, Rust module under 500 (§15.1).
- Naming: components `PascalCase.tsx`, lib and stores `camelCase.ts`, Rust `snake_case`; IPC commands `domain_verb` in snake_case; events `kebab-case` (§15.1, this document).
- Commits follow Conventional Commits (§15.4). Every task ends with the quality gates in §15.4 passing for the code it touched: before each task's commit step run `npm run typecheck && npm run lint && npx vitest run src/features/canvas` (Task 9 and Task 15 also run `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings`; Task 17 also runs `npm run e2e` and `npm run build`).
- Canvas-specific, from §10.7 and §11.3: the model is pure and lives apart from rendering; the 300 ms spring and the 150 ms reduced-motion ease are the only two position transitions; a shared file pulses once, never loops.

## Review Focus

1. A dispatch description that drops or changes the middle dot (`Step 5 - frontend: …`, `step 5 · Frontend:`) — the agent must still appear, attributed where the text allows, never crash the model. Test in Task 2 (`parseDispatch accepts a hyphen or em dash separator and is case-insensitive`).
2. Duplicate or out-of-order events after a relaunch (the tailer replays the log; a `seq` can arrive twice) — the canvas must show each edit once. Test in Task 1 (`normalizeEvents drops duplicate seqs and sorts ascending`).
3. A `SubagentStop` (or `PostToolUse Task`) whose start was never seen (log began mid-build) — no phantom agent node. Test in Task 2 (`ignores a SubagentStop without a matching start`).
4. Saved positions for nodes that no longer exist (the agent rewrote `plan.md`) — ignored on load, pruned on the next save, no orphan cards. Test in Task 7 (`prunePositions drops ids that are not in the graph`) and Task 10 (`persists positions once, 500 ms after a drag settles, and only for current nodes`).
5. A 20,000-event log scrubbed with the replay slider — derivation must stay linear so each scrub position renders inside the 250 ms budget. Test in Task 5 (`derives a 20,000-event stream in under one second`).

### Task 2: Dispatch attribution and agent derivation

**Files:**

**Interfaces:**
- Consumes: `events.ts` accessors and `ORCHESTRATOR_ID` (Task 1); `fx`, `sampleBuild` (Task 1).
- Produces:
  - `parseDispatch(description: string): { steps: number[]; role: string } | null` — matches `/^\s*step\s+(\d+(?:\s*,\s*\d+)*)\s*[·\-—:]\s*([^:]+):/iu`; `steps` are the listed integers in order, `role` trimmed and lower-cased
  - `type AgentRecord = { agentId: string; role: string; adhoc: boolean; working: boolean; steps: number[]; description: string | null; startedSeq: number; stoppedSeq: number | null }`
  - `deriveAgents(events: TaskEvent[]): AgentRecord[]` — always begins with the orchestrator `{ agentId: "main", role: "orchestrator", adhoc: false, working: mainWorking(events), steps: [], startedSeq: 0 }`; one record per `SubagentStart` keyed by `agent_id`; `description` is `SubagentStart.description` when present, else the oldest unmatched `PreToolUse Task` description from the same window of events (FIFO); `role` is `parseDispatch(description).role` when that parses, else `agent_type`; `adhoc` is true when `agent_type` is `"general-purpose"` or the role came from the dispatch text and differs from `agent_type`; `working` is true until a matching `SubagentStop`; a `PreToolUse Task` whose `PostToolUse Task` arrives with no `SubagentStart` in between becomes a record `agentId: "dispatch:<preSeq>"` spanning pre→post; a `SubagentStop` with no start is ignored
  - `mainWorking(events: TaskEvent[]): boolean` — true when the last of {`SessionStart`, `UserPromptSubmit`, `Stop`, `StopFailure`} is `UserPromptSubmit`, or is a `Stop` with `background_tasks > 0`; false when no such event exists

# Team Code 08 — Task Page and Dock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the task page that opens in a pane: the header with stepper and per-stage primary action, the Spec-stage editor with the LiveSpec switch, and the dock (⌘J, or a right inspector) with its Memory, Changes (CodeMirror 6 diff with reviewer notes), Ticket, Test and Commit tabs, plus the Team slot Plan 09 fills.

**Architecture:** Four feature folders, `task-page`, `dock`, `changes` and `spec-editor`, each with a module store built on Plan 01's `createStore` and read with `useSyncExternalStore`. The `Task` records themselves are not copied: the page reads them from Plan 06's shared `tasksStore` through a one-file adapter, and the shell passes `projects` from Plan 06's `projectsStore`. Every decision that depends on stage and state (which button, which dock tab, which memory file) is a pure function with its own test; every store that touches IPC takes its command set as a constructor parameter so Vitest drives it with a fake command layer. LiveSpec's `DraftPane`, `NotesPane` and `MiniMarkdown` in `src/livespec/` are adapted in place to Plan 02 primitives and the Team Code tokens; its `TabSession` becomes a file-bound `SpecSession` in the spec-editor feature.

**Tech Stack:** React 19, TypeScript 5 strict, Vite, Tailwind v4 semantic tokens, CodeMirror 6 (`@codemirror/state`, `@codemirror/view`, `@codemirror/merge`, `@codemirror/language-data`), Motion, Vitest with jsdom and `@testing-library/react`, tauri-specta bindings in `src/lib/bindings.ts`.

**Spec:** `docs/superpowers/specs/2026-10-24-team-code-design.md` §6.1–§6.6, §10.3, §10.5 (⌘J, ⌘⇧J, ⌘⏎, ⌘E, ⌘⇧A, ⌃`), §10.6, §10.7 (Placement), §14, §15. Contracts: `docs/superpowers/plans/2026-10-24-team-code-00-overview-and-contracts.md`; every name below that is not introduced here comes from that document verbatim.

## Global Constraints

- Three layers: `crates/teamcode-core` never depends on Tauri; `src-tauri` stays thin; the webview has no state library and uses module stores read with `useSyncExternalStore` (§3, §14).
- IPC types are generated by `tauri-specta` into `src/lib/bindings.ts`; hand-written mirrors are forbidden (§15.1).
- Raw `<input>`, `<select>`, `<textarea>`, `<button>`, `<dialog>` appear only under `src/components/ui/`; hex colours and inline colour styles appear only in the theme file. ESLint fails the build otherwise (§15.3).
- Semantic Tailwind tokens only: `bg-page`, `bg-bar`, `bg-well`, `bg-card`, `border-line`, `text-ink`, `text-mute`, `text-accent`, `text-ok`, `text-warn`, `text-bad`, plus `stage-spec|plan|build|review|test|commit|done` (§11.1).
- Fonts bundled from Fontsource, never fetched: Inter, JetBrains Mono, Literata. CSP `default-src 'self'` (§3, §14).
- Every id that becomes a path matches `^[a-z]+-[0-9a-f-]{1,40}$` before use (§14).
- Model and agent output renders only through `MiniMarkdown` or xterm, never `innerHTML` (§14).
- The app never commits, merges, rebases, pushes or deletes branches on its own; the Commit button exists only when "Team Code may commit" is on, default off (§6.6).
- Nothing a user triggers takes longer than 250 ms to respond; `prefers-reduced-motion` turns springs into 150 ms eases and stops loops (§11.3).
- File size budgets: component under about 200 lines, store under 300, Rust module under 500 (§15.1).
- Naming: components `PascalCase.tsx`, lib and stores `camelCase.ts`, Rust `snake_case`; IPC commands `domain_verb` in snake_case; events `kebab-case` (§15.1).
- A feature imports another feature only through its `index.ts`, never its store or internals (§15.1).
- Commits follow Conventional Commits (§15.4). Every task ends with the quality gates in §15.4 passing for the code it touched: `npm run typecheck`, `npm run lint`, `npx vitest run`.

## Conventions every task in this plan uses

- **Bindings.** A contract command `git_changes` is called as `commands.gitChanges(...)` from `src/lib/bindings.ts` (tauri-specta's camelCase export); a contract event `task-changed` is subscribed as `events.taskChanged.listen(cb)`. A call resolves to its value and rejects with the serialised `Error` string (Plan 01's bindings wrapper); fakes in tests do the same. Enums follow amendment A1: every data-carrying enum is internally tagged with `type`, so its unit variants are objects too: `AgentState` is `{ type: "Idle" }`, `{ type: "Working" }`, `{ type: "NeedsYou", reason: { type: "StageDone" } }`, `{ type: "NeedsYou", reason: { type: "Replied", first_line: "…" } }`, `{ type: "NeedsYou", reason: { type: "TestFailed", exit_code: 1 } }`; `StageAction` is `{ type: "Approve" }`, `{ type: "Back", stage: "Plan" }`, `{ type: "Reply", prompt: "…" }`; `HookEvent` is `{ type: "StatusLine", cost_usd, … }`. Unit-only enums (`Stage`, `LiveSpecLevel`, `DockPosition`, `TeamViewPlacement`, `ChangeStatus`) stay plain strings. `src/features/task-page/agentState.ts` (Task 6) is the only file that branches on `AgentState`; every hand-back chip or state text comes from `handbackLabel(task)` in `src/lib/format.ts` (Plan 06, A2), never from a local mapping.
- **Stores.** `createStore<T>(initial)` from `src/lib/stores/createStore.ts` (Plan 01, A10) returns `{ get, set, subscribe, use, useSelector, reset }`; components read with `store.use()` or `store.useSelector(selector)`, and render tests that share a module store call `reset()` in `afterEach`. Interfaces below write a store's type as `ReturnType<typeof createStore<T>>`. Each IPC-touching store is `createXStore(ipc, …)` with a module-level `xStore = createXStore(commands)`; tests build their own with a fake `ipc` object of `vi.fn()`s. Task and project records come from Plan 06's `src/lib/stores/tasksStore.ts` and `projectsStore.ts` (A10), never from a store in this plan.
- **Motion.** Animated layout changes (the dock growing, the Swap body change) take their transition from Plan 02's `src/lib/motion.ts`: `transitionFor(kind, useReducedMotion())`; no spring constants are defined in this plan.
- **Tests.** Store and pure-logic tests run in node; render tests start with `// @vitest-environment jsdom` and use `render`/`screen`/`fireEvent` from `@testing-library/react` (Task 1 adds `@testing-library/react` and `jsdom` as dev dependencies if Plan 02 did not). Fake timers via `vi.useFakeTimers()`.
- **Primitives.** Controls come from `src/components/ui` (Plan 02): `Button`, `IconButton`, `Input`, `Textarea`, `Segmented`, `Tabs`, `Menu`, `Popover`, `Tooltip`, `Dialog`, `Chip`, `Badge`, `Avatar`, `KeyHint`, `StatusDot`, `EmptyState`, `Panel`, `Resizable`, `Toast`, `Switch`, `Field`.
- **Fixtures.** `src/features/task-page/testing/fixtures.ts` (Task 7) exports `makeTask(overrides?)`, a `Task` in `Plan` with `state: { type: "Idle" }`, `id: "task-1"`, `project_id: "proj-1"`, `primary_session: "sess-1"`, `linked_roots: ["/b"]`; `makeTaskSource(tasks?)`, an in-memory `TaskSource` (Task 7); `makeSettings(overrides?)`, a `TaskSettings` with every flag off, `testCommand: null`, `dockPosition: "Bottom"`, `teamViewPlacement: "DockGrows"`; and `fakeEvents`, an `events` stand-in whose every `listen` resolves to a no-op unsubscribe. Render tests of components that subscribe to events start with `vi.mock("@/lib/bindings", () => ({ commands: fakeCommands, events: fakeEvents }))`. Imports use the `@/` alias for `src/` that Plan 01 configures.

## Review Focus

1. A `review.md` note whose line is past the end of the file, or whose file is not in the change set: the note must still be reachable (clamped to the last line, or listed under "Notes on files outside the change set"), never silently dropped. Tests in Tasks 12 and 14.
2. Saving the working-tree side after the agent changed that file underneath the editor: the save must not clobber the agent's edit without saying so. Task 13 marks the buffer `staleOnDisk` on a `git-changes` event and the editor offers Reload or Overwrite.
3. A task whose memory folder was deleted ("memory missing", §8): `memory_read` rejects with a `Precondition` message; the Memory tab and the Spec editor show it verbatim and disable editing instead of writing an empty file. Tests in Tasks 4 and 11.
4. "Approve spec" pressed while the autosave of `spec.md` has failed: the stage must not advance on a spec that is not on disk. Task 4 flushes the saver and refuses the advance on failure.
5. A `task-changed` for a stage change arriving while the developer has unsaved edits in the Memory tab editor: the live re-read must not replace their buffer. Task 11's `shouldReload` returns false while dirty.

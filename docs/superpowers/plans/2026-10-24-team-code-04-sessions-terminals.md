# Team Code 04 — Sessions and Terminals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every task and plain terminal a Rust-owned PTY behind the `SessionDriver` trait (Owned implementation), launch Claude Code, Codex and shells with the right flags and a generated per-task settings file, inject stage prompts only when the agent is idle, keep scrollback and attachments alive across pane, view and window switches, and render it all in an xterm.js pane.

**Architecture:** `teamcode_core::sessions` holds everything that can be tested without a terminal: the scrollback ring, output batching and flow control, the `SessionDriver` trait and `OwnedDriver`, the launch argument builders and settings-file writer, the idle tracker and injection queue, and a `SessionRegistry` that enforces one attachment per session. The shell's `src-tauri/src/pty.rs` wraps `portable-pty` behind the core's `PtySpawner` trait, `commands/sessions.rs` exposes the `sessions_*` commands, and `session_service.rs` wires effects, hook events and quit handling. The webview's `TerminalPane` owns one xterm instance, attaches through `terminalStore`, and reads its palette from CSS variables so no hex colour leaves `styles.css`.

**Tech Stack:** Rust stable, `portable-pty`, `serde_json`, Tauri 2 (`Channel`, `tauri-specta`, `tauri-plugin-dialog`), React 19, TypeScript 5 strict, `@xterm/xterm` with `@xterm/addon-fit`, `@xterm/addon-webgl`, `@xterm/addon-canvas`, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-24-team-code-design.md` §7.1–7.3, §7.5 (launch side), §9 (launch side), §11.2, §13, §16; contracts in `docs/superpowers/plans/2026-10-24-team-code-00-overview-and-contracts.md`.

**Build order (overview A18):** 01, 02, 03, 05, **04**, then 06 and 07, then 08 and 09, then 10. This plan builds after Plan 05 and imports `hooks::{HookSpec, HookEvent, TaskEvent}` from it; the dependency is one-way, so Plan 05 never calls into this plan, and this plan registers its `note_hook_event` with Plan 05's `hooks_tailer::subscribe` at startup (Task 11).

## Global Constraints

- macOS first, Apple Silicon first; code kept portable (spec §2).
- Tauri 2; Rust stable; Node 22; React 19; TypeScript 5.x strict; Vite; Tailwind v4 via `@tailwindcss/vite`, no `tailwind.config` (§3, LiveSpec convention).
- Three layers: `crates/teamcode-core` never depends on Tauri; `src-tauri` stays thin; the webview has no state library and uses module stores read with `useSyncExternalStore` (§3, §14).
- IPC types are generated by `tauri-specta` into `src/lib/bindings.ts`; hand-written mirrors are forbidden (§15.1).
- Raw `<input>`, `<select>`, `<textarea>`, `<button>`, `<dialog>` appear only under `src/components/ui/`; hex colours and inline colour styles appear only in the theme file. ESLint fails the build otherwise (§15.3).
- Semantic Tailwind tokens only: `bg-page`, `bg-bar`, `bg-well`, `bg-card`, `border-line`, `text-ink`, `text-mute`, `text-accent`, `text-ok`, `text-warn`, `text-bad`, plus `stage-spec|plan|build|review|test|commit|done` (§11.1).
- Fonts bundled from Fontsource, never fetched: Inter, JetBrains Mono, Literata. CSP `default-src 'self'` (§3, §14).
- Secrets live in the OS keychain under service `app.teamcode.desktop`, never cross IPC (§14).
- Every id that becomes a path matches `^[a-z]+-[0-9a-f-]{1,40}$` before use (§14).
- Model and agent output renders only through `MiniMarkdown` or xterm, never `innerHTML` (§14).
- Nothing a user triggers takes longer than 250 ms to respond; `prefers-reduced-motion` turns springs into 150 ms eases and stops loops (§11.3).
- File size budgets: component under about 200 lines, store under 300, Rust module under 500 (§15.1).
- Naming: components `PascalCase.tsx`, lib and stores `camelCase.ts`, Rust `snake_case`; IPC commands `domain_verb` in snake_case; events `kebab-case` (§15.1, contracts).
- Commits follow Conventional Commits (§15.4). Every task ends with the quality gates in §15.4 passing for the code it touched.
- Plan-specific, from the spec: terminal output batched at about 60 Hz, no dropped frames (§7.1, §16); scrollback default 10,000 lines (§13); graceful end is `/exit`, then up to 5 s, then kill (§7.1); idle CPU with 10 attached terminals under 1 % (§16); the generated settings file carries only hooks, status line, protected-root deny rules and, when needed, the background-isolation key (§14); the app never writes into a project's `.claude/` folder (§7.3).

## Review Focus

1. A 50 MB burst (an agent `cat`s a build log): the reader must pause when 1 MiB is unacknowledged and resume below 256 KiB, with nothing dropped and the UI still responsive — pinned by `FlowControl` tests (Task 2), the gate test in Task 9 and the ack coalescing test in Task 14.
2. A window is closed while a pane is attached: the process keeps running, the attachment is cleared, and the next pane that opens the task attaches without "already attached elsewhere" — pinned by `detach_window_keeps_process_and_clears_attachment` (Task 4) and the window-destroyed hook in Task 10.
3. The agent exits while prompts sit in the "will send when idle" queue: the queue is cleared, `session-queue-changed {pending: 0}` goes out, and nothing is written to the dead PTY — pinned by `exit_clears_queue_and_sink` (Task 4) and `apply_effects` behaviour in Task 11.
4. `claude` (or `codex`, or the shell) is not on PATH: `sessions_open` fails with `Error::Precondition` naming the binary instead of a session that dies silently — pinned by `spawn_unknown_program_is_precondition` (Task 9).
5. A pane collapsed to a strip (Spec stage) makes the fit addon report 0 columns or rows: the PTY never receives a 0×0 resize — pinned by `resize_clamps_to_minimum` (Task 4) and the fit guard in Task 15.

# Team Code 05 — Observation: hooks, git, helpers, cost — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything Team Code *observes* about a running task: the hook commands and durable per-task event log, the tailer that turns log lines into typed events and drives the pipeline, the task's change set over git, both worktree conventions, Commit-stage Done detection, the owned test runner, the headless helpers (naming, spec watcher, commit messages, project briefs), the LiveSpec Simple/Heavy mapping and the Spec stage's LiveSpec run, the cost ledger, and the board's activity snapshot.

**Architecture:** All logic lives in `crates/teamcode-core` (modules `hooks`, `git`, `worktree`, `changes`, `testrun`, `helpers`, `cost`, `activity`), unit-tested against fixtures: sample event-log lines, a temp git repo, a sample transcript JSONL, a one-shot local SSE server standing in for the model. The shell adds three thin watchers (`hooks_tailer.rs`, `git_watcher.rs`, the test runner's replay buffer) and the `git_*`, `tests_*`, `hooks_*`, `cost_*`, `livespec_*` and `tasks_activity` commands. Model calls go only through `livespec_core::llm::Provider` and are metered by `livespec_core::usage`; git goes only through the `git` binary.

**Tech Stack:** Rust stable, `tokio` (process, fs, time), `serde_json`, `chrono`, `rusqlite` (via Plan 01's `db`), `notify = "8"` (shell only), `tempfile` (dev), `livespec-core` unchanged.

**Spec:** `docs/superpowers/specs/2026-10-24-team-code-design.md` (§6.1, §6.3–6.6, §7.3–7.4, §9, §10.6, §10.7 "Data", §14, §17). Contracts: `docs/superpowers/plans/2026-10-24-team-code-00-overview-and-contracts.md`.

**Build order (overview A18):** 01, 02, 03, **05**, 04, then 06 and 07, then 08 and 09, then 10. This plan builds before Plan 04 and imports nothing from it: Plan 04 imports `HookSpec`, `HookEvent` and `TaskEvent` from here and registers its `note_hook_event` through `hooks_tailer::subscribe` (Task 9).

## Global Constraints

- Three layers: `crates/teamcode-core` never depends on Tauri; `src-tauri` stays thin; the webview has no state library and uses module stores read with `useSyncExternalStore` (§3, §14).
- IPC types are generated by `tauri-specta` into `src/lib/bindings.ts`; hand-written mirrors are forbidden (§15.1).
- Secrets live in the OS keychain under service `app.teamcode.desktop`, never cross IPC (§14).
- Every id that becomes a path matches `^[a-z]+-[0-9a-f-]{1,40}$` before use (§14).
- The app never commits, merges, rebases, pushes or deletes branches on its own; the Commit button exists only when "Team Code may commit" is on, default off (§6.6).
- Nothing a user triggers takes longer than 250 ms to respond (§11.3): every command here returns at once or streams over a `Channel`.
- File size budgets: Rust module under 500 lines (§15.1).
- Naming: Rust `snake_case`; IPC commands `domain_verb` in snake_case; events `kebab-case`. Serde (overview A16): no `rename_all` anywhere; struct fields reach JSON and `bindings.ts` in `snake_case` exactly as written (`task_id`, `cost_usd`, `current_file`, `first_line`), variants keep their Rust names (`"NeedsYou"`).
- Commits follow Conventional Commits (§15.4). Every task ends with `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings` passing for the code it touched.
- The app runs git through the `git` binary, never a bundled library (§9). The app never reads Claude Code's token files (§3). `livespec-core` is copied unchanged (§14).
- Hooks or prompts the app installs never leak into the developer's normal Claude Code usage (§2): the hook commands exist only in the per-task generated settings file Plan 04 writes.

## Review Focus

1. **A hook line that is incomplete or malformed.** The hook command buffers the payload and appends one line in one write (overview A3), but the app may still read `<task-id>.jsonl` mid-append, and a crashed hook can leave junk. Expected: a partial tail waits for its newline; a line whose payload is not JSON is kept as `Unknown` and never stops the tailer. Tests: Task 2 `split_complete_lines_keeps_the_partial_tail`, `a_payload_that_is_not_json_is_preserved_as_unknown`.
2. **Paths with spaces, renames and deletions in `git status`.** Expected: parsed exactly, attributed to the right repo. Tests: Task 5 `status_handles_spaces_and_renames`, Task 7 `files_are_grouped_by_repo_by_longest_prefix`.
3. **The same transcript usage written on several lines.** Claude Code repeats `message.usage` on every content-block line of one assistant message. Expected: counted once per `message.id`. Test: Task 16 `usage_is_counted_once_per_message_id`.
4. **The spec watcher triggering itself.** When the memory folder lives inside the repo, the watcher's write to `spec.md` is itself a git change. Expected: changes only under `memory_dir` never trigger a run; an identical rewrite is dropped. Tests: Task 13 `changes_only_under_the_memory_dir_do_not_trigger`, `an_identical_rewrite_is_dropped`.
5. **A worktree Claude Code removed between stages, or a `tc/<slug>` branch that already exists.** Expected: the next launch recreates the worktree from the same name; a managed create reuses the branch instead of failing on `-b`. Tests: Task 6 `a_missing_claude_worktree_is_recreated_from_the_same_name`, `create_managed_reuses_an_existing_branch`.

`hook_specs` builds one `HookSpec` per `HOOK_EVENTS` entry with `command: hook_command(event, &event_log_path(..))`, `matcher: None`, `timeout_s: Some(5)` (Claude Code hook `timeout` is in seconds). `hook_command` is overview A3's line verbatim: `sh -c 'IN=$(cat); printf "%s\t%s\t%s\n" "<EventName>" "$(date -u +%FT%TZ)" "$IN" >> "<log>"'`; the payload is read whole before the single `printf`, so parallel subagent hooks append whole lines. - [ ] **Step 3: Implement `hooks/parse.rs`**

`splitn(3, '\t')`; fewer than three fields → `Error::Invalid`. The variant is chosen from the line's first field (the `<EventName>` the hook command wrote), never from the payload's `hook_event_name` and never by deserialising the payload as `HookEvent`: the `type` tag (A1) is the IPC shape only, and Claude's payload carries no `type`. Timestamp parsed with `DateTime::parse_from_rfc3339`. Payload JSON failing to parse → `Unknown { name }`. Field mapping: `SessionStart{session_id, transcript_path}`, `PreToolUse{tool: tool_name, input: tool_input}`, `PostToolUse{…, response: tool_response}`, `SubagentStart{agent_id (normalised), agent_type, description: None}`, `SubagentStop{agent_id}`, `PermissionRequest{tool: tool_name}`, `Notification{message}`, `Stop{last_assistant_message, background_tasks: background_tasks.as_array().len()}`, `StopFailure{message: last_assistant_message | error_details | error}`, `StatusLine{cost.total_cost_usd, context_window.total_input_tokens, context_window.total_output_tokens, context_window.used_percentage (null → 0.0)}`. Missing fields default to `""`, `Value::Null` or `0`. `TaskEvent.agent_id` = payload `agent_id` normalised when present.

# Team Code 03 — Core Domain and Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Tauri-free heart of Team Code in `crates/teamcode-core`: the pipeline state machine with hand-back detection, task memory folders on disk, layered stage prompts and the shipped templates, the subagent roster, scoped settings, the SQLite repositories for projects, tasks, views and settings, the pure view-layout operations, and the thin shell commands and events that expose them.

**Architecture:** Every rule lives in `teamcode-core` as pure functions over the contract types (`transition` returns `Effect`s, it never touches a PTY or git); `pipeline::apply` persists the persistence-shaped effects (stage, state, archive flag, timeline) to SQLite and `index.md` in one transaction and hands the external ones (`StartSession`, `InjectPrompt`, `CreateWorktree`, `RunTest`, `RunHelper`) back to the shell for Plans 04 and 05 to run. Files follow LiveSpec: atomic writes, a file that does not parse is set aside as `.bad`, never overwritten; ids are validated before they become paths.

**Tech Stack:** Rust stable, `rusqlite` (bundled), `serde`/`serde_json`, `specta` derives, `chrono`, `tempfile` (dev), Tauri 2 + `tauri-specta` in `src-tauri` only.

**Spec:** `docs/superpowers/specs/2026-10-24-team-code-design.md` (§5, §6, §6.8, §7.5, §8, §13, §14). Contracts: `docs/superpowers/plans/2026-10-24-team-code-00-overview-and-contracts.md`. Both travel with this plan; names come from the contracts verbatim.

## Global Constraints

- macOS first, Apple Silicon first; code kept portable (spec §2).
- Tauri 2; Rust stable; Node 22; React 19; TypeScript 5.x strict; Vite; Tailwind v4 via `@tailwindcss/vite`, no `tailwind.config` (§3, LiveSpec convention).
- Three layers: `crates/teamcode-core` never depends on Tauri; `src-tauri` stays thin; the webview has no state library and uses module stores read with `useSyncExternalStore` (§3, §14).
- IPC types are generated by `tauri-specta` into `src/lib/bindings.ts`; hand-written mirrors are forbidden (§15.1).
- Secrets live in the OS keychain under service `app.teamcode.desktop`, never cross IPC (§14).
- Every id that becomes a path matches `^[a-z]+-[0-9a-f-]{1,40}$` before use (§14).
- The app never commits, merges, rebases, pushes or deletes branches on its own; the Commit button exists only when "Team Code may commit" is on, default off (§6.6).
- Nothing a user triggers takes longer than 250 ms to respond (§11.3): every command here is synchronous SQLite and small file I/O; nothing waits on a model or a process.
- File size budgets: component under about 200 lines, store under 300, Rust module under 500 (§15.1). The prompt templates and the shipped agents are string constants in their own files and are exempt from the budget, nothing else is.
- Naming: Rust `snake_case`; IPC commands `domain_verb` in snake_case; events `kebab-case` (§15.1, contracts).
- Commits follow Conventional Commits (§15.4). Every task ends with `cargo test -p teamcode-core` and `cargo clippy --workspace --all-targets -- -D warnings` passing for the code it touched.
- Tests sit beside the code (`#[cfg(test)] mod tests` in each module, `tempfile::tempdir()` for disk, `Connection::open_in_memory()` plus `db::migrate` for SQLite). No test touches the network, a PTY or `git`.

## Review Focus

1. A sentinel line wrapped in markdown (`**TEAMCODE: plan done**`, `` `TEAMCODE: plan done` ``), with trailing spaces, or followed only by blank lines must still count; the same text quoted mid-message ("I will end with TEAMCODE: plan done") must not. Pinned in Task 5.
2. Dragging a card into Test when the home project has no test command must be refused with an instruction (`Error::Precondition`) and leave the card where it was; the same drag with a command set must run the tests. Pinned in Task 7.
3. A task whose memory folder was deleted stays on the board: reads return `None`, stage actions still persist to SQLite, the card reports memory missing, nothing recreates the folder silently; a corrupt `index.md` is set aside as `index.md.bad` and never overwritten. Pinned in Tasks 4 and 14.
4. A title with slashes, emoji, 300 characters or only punctuation must still produce a safe, bounded folder name, and two tasks created the same day with the same title must get distinct folders. Pinned in Task 2.
5. `settings_set` with an unknown key, a value of the wrong type, or a key at a level that does not allow it must fail with `Error::Invalid` and store nothing. Pinned in Task 11.

The contract types in `domain.rs` derive `Debug, Clone, PartialEq, Serialize, Deserialize, specta::Type` with no `rename_all` anywhere (amendment A16): struct fields serialise in `snake_case` exactly as written in Rust, unit-only enums serialise as their Rust variant names (`"Spec"`, `"ClaudeCode"`, `"AppStorage"`), and every data-carrying enum is internally tagged with exactly `#[serde(tag = "type")]` (amendment A1), so the tag is the variant name and variant fields keep their Rust names: `AgentState::NeedsYou { reason: HandbackReason }` serialises as `{"type":"NeedsYou","reason":{"type":"Replied","first_line":"…"}}`. Every variant of a tagged enum is a unit or struct variant (A17): `Container::Project { id }`, `Container::Workspace { id }`, `MemoryLocation::AppStorage`, `MemoryLocation::Folder { path }`, `PaneContent::Empty`, `PaneContent::Task { task_id }`, `PaneContent::TeamCanvas { task_id }`, `PaneContent::Terminal { project_id, session_id }`; this plan's tests build them in exactly those shapes. `Task` carries A11's `state_entered_at: DateTime<Utc>` and `links_bound_at: Option<DateTime<Utc>>` (Plan 01 adds the fields; this plan adds their columns in `0003_core` and persists them). Serde cannot internally tag a tuple variant, nor a newtype variant around a string or another tagged enum, so this plan's own serialised enums use struct variants (`StageAction::Back { stage }`, `StageAction::Reply { prompt }`) and `Effect`, which never crosses IPC or disk, is not serialised.

- Consumes: `teamcode_core::{Error, Result}` (Plan 01 `error.rs`; `Error::Io(String)` for I/O failures, built with `Error::Io(e.to_string())`).
- Produces:
  - `pub enum Loaded<T> { Missing, Parsed(T), Corrupt { kept: Option<PathBuf> } }`
  - `pub fn write_atomic(path: &Path, bytes: &[u8]) -> Result<()>` — writes `<file>.tmp` beside the target, renames over it, creates parent dirs.
  - `pub fn set_aside(path: &Path) -> Option<PathBuf>` — renames to the first free `<name>.bad`, `<name>.bad.1`, …; never replaces an earlier copy.
  - `pub fn load_text(path: &Path) -> Result<Loaded<String>>` — `Missing` on NotFound, `Parsed` on valid UTF-8, `Corrupt { kept }` (file set aside) on invalid UTF-8; any other read error is `Err` and the file is left in place.
  - `pub fn load_with<T>(path: &Path, parse: impl FnOnce(&str) -> Option<T>) -> Result<Loaded<T>>` — same, applying `parse`; `None` from `parse` means corrupt.
  Used by Tasks 3, 4, 9, 10 and by Plan 10 for workspace files.

### Task 3: `index.md` front matter and timeline (`memory::index`)

**Files:**

```rust
pub struct IndexFrontMatter { pub id: TaskId, pub project: ProjectId, pub workspace: Option<WorkspaceId>,
    pub title: String, pub stage: Stage, pub state: StateWord, pub jira: Option<String>, pub agent: AgentKind,
    pub branch: Option<String>, pub worktree: Option<PathBuf>, pub base: Vec<RepoBase>,
    pub claude_sessions: Vec<String>, pub created: DateTime<Utc>, pub updated: DateTime<Utc> }
pub enum StateWord { Working, NeedsYou, Idle }           // `working` | `needs-you` | `idle`; from_state(&AgentState)
pub struct IndexEntry { pub at: DateTime<Utc>, pub stage: Stage, pub kind: TimelineKind }
pub enum TimelineKind { Created, Entered, Exited, Skipped, Handback { chip: String },
    Commit { repo: String, sha: String }, Archived, Restored }
pub struct IndexDoc { pub front: IndexFrontMatter, pub timeline: Vec<IndexEntry> }
pub fn render(doc: &IndexDoc) -> String
pub fn parse(text: &str) -> Option<IndexDoc>          // None when the front matter is unreadable
pub fn render_entry(e: &IndexEntry) -> String          // one timeline line, no trailing newline
```

  Format, fixed by the contract: the file starts with `---`, one `key: value` line per key in the order `id, project, workspace, title, stage, state, jira, agent, branch, worktree, base, claude_sessions, created, updated`, then `---`, a blank line, `## Timeline`, a blank line, one `- ` line per entry. Optional keys with no value render as `key:` (nothing after the colon). `base:` renders its map as indented `  <repo_root>: <sha>` lines; `claude_sessions:` as indented `  - <id>` lines; both render just the key when empty. `agent` renders `claude-code | codex | shell`; `worktree` renders the path or `off`. Timestamps in the front matter are RFC 3339 seconds (`2026-10-24T05:12:33Z`); timeline lines use minutes as the contract shows: `- 2026-10-24T05:12Z · plan · entered`. Kinds render as `created`, `entered`, `exited`, `skipped`, `handback: <chip>`, `commit: <repo> <sha>`, `archived`, `restored`. `parse` splits each line on the first `: ` (so a title may contain colons) and parses timeline lines back; a timeline line it cannot parse is skipped, a front matter it cannot parse makes the whole document `None`.

pub enum StageAction { Approve, Advance, Back { stage: Stage }, Reply { prompt: String }, StartFresh, RequestReview, ApproveChanges, RunTests, FixTests, CopyCommit, Commit, Archive, Restore }

  `enter(stage)` is the one place a stage's entry effects are defined (forward moves, `Back`, and column skips all call it). Effects, in this order:
  - Spec: `SetStage(Spec)`, then if `task.primary_session.is_some()` and `agent_kind != Shell`: `InjectPrompt(prompts.spec)`, `SetState(Working)`; else `SetState(Idle)`. Never starts a session.
  - Plan: `SetStage(Plan)`; if `task.worktree == On && task.worktree_path.is_none() && task.primary_session.is_none()`: `CreateWorktree`; if `task.primary_session.is_none()`: `StartSession`; if `agent_kind != Shell`: `InjectPrompt(prompts.plan)`, `SetState(Working)`; else `SetState(Idle)`.
  - Build: `SetStage(Build)`, `StartSession` if none, then prompt as in Plan with `prompts.build`.
  - Review: `SetStage(Review)`, `StartSession` if none, prompt with `prompts.review`, then `RunHelper(SpecWatcher)`.
  - Test: `Precondition("Set a test command in project settings before using the Test stage")` when `ctx.test_command.is_none()`; else `SetStage(Test)`, `RunTest`, `SetState(Working)`.
  - Commit: `SetStage(Commit)`, `RunHelper(CommitMessages)`, `SetState(Working)`.
  - Done: `SetStage(Done)`, `SetState(Idle)`, `Toast("Task done")`.
  `transition` per action (anything else is `Error::Invalid("<action> is not available in <stage>")`):
  - `Approve`: Spec only → `WriteIndex(Handback "Spec ready" at Spec)` then `enter(Plan)`.
  - `Advance`: Spec → as Approve; Plan/Build/Review/Test/Commit → `enter(next_stage)`; Done → `Precondition("Already done")`.
  - `RequestReview`: Build only → `enter(Review)`.
  - `ApproveChanges`: Review only → `enter(next_stage)`.
  - `RunTests`: Test only → `[RunTest, SetState(Working)]`.
  - `FixTests`: Test only, requires `ctx.last_test` with `exit_code != 0` and `prompts.fix_tests` Some, else `Precondition("Run the tests first")` → `SetStage(Build)`, `StartSession` if none, `InjectPrompt(fix_tests)`, `SetState(Working)`.
  - `CopyCommit`: Commit only → `[Toast("Commit message copied")]` (the webview copies; this records intent and keeps the action in one place).
  - `Commit`: Commit only; `may_commit` false → `Precondition("Turn on \"Team Code may commit\" in project settings to commit from here")`; else `[RunHelper(GitCommit)]`. Done detection (the move to Done when every repo is committed) is Plan 05's and arrives as `transition(task, Advance, ctx)` from Commit.

Allowed in any agent state: Plan 04 holds the prompt until the session is idle. The state flips to Working on the next `UserPromptSubmit` (Plan 05), not here.
  - `StartFresh`: Plan/Build/Review and `agent_kind != Shell` → `EndSession` if a session exists, `CreateWorktree` if `worktree == On && worktree_path.is_none()`, `StartSession`, `InjectPrompt(prompt for task.stage)`, `SetState(Working)`. Plan 04 treats `EndSession` followed by `StartSession` as "fresh": no `--resume`, `claude_session_id` cleared.
  - `Back { .. }`, `Archive`, `Restore`: implemented in Task 7 (`move_to.rs`); until then return `Invalid`.
